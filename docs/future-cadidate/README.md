# Future Candidate Docs

## Purpose

This folder holds parked future capability candidates for Neon Ronin.

These documents preserve ideas that may become useful later, but they are not active roadmap work, implementation plans, schema authority, runtime authority, or agent authority.

Read these docs only as future context.

Do not take action from these docs unless a current roadmap decision, implementation-start decision, or explicit human instruction promotes a candidate into active work.

## Rules

Future-candidate docs must:

- stay business-neutral unless clearly marked as workspace-originated pressure
- avoid becoming core doctrine
- avoid authorizing implementation
- avoid authorizing agents, runtime behavior, integrations, scheduled jobs, watch mode, Observatory ingestion, customer-facing work, SearchClarity onboarding, or automation
- avoid creating schemas, persistence tables, domain records, or workflow records
- identify what evidence would be needed before the idea can move forward
- identify what is explicitly not authorized

## How To Use This Folder

Use this folder when an idea is worth remembering but not worth acting on yet.

Good fit:

- reusable platform capability candidates
- cross-workspace patterns noticed during planning
- future agent-assistance concepts
- future review-gate concepts
- future data/record implications that need more evidence

Bad fit:

- active implementation plans
- current roadmap steps
- workspace-specific operating docs
- SearchClarity business docs
- prompts
- schemas
- code plans ready for execution

## Promotion Rule

A future candidate may move toward active work only after a separate human decision identifies:

- why the capability is needed now
- which workspace evidence supports it
- whether it belongs in core, workspace config, adapter/integration, or remains out of scope
- what review gates are required
- what is explicitly forbidden
- whether implementation, docs-only planning, tests-only validation, or continued deferral is appropriate

Until then, future-candidate docs are parked context only.
